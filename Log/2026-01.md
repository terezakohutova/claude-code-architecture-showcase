# Log - January 2026

### 2026-01-22 - CLOSED_Added a second escalation path: TUNING-LEDGER.md and procedure-tuner

The style-guard escalation (documented rule -> repeated drift -> hard hook)
only catches problems in content a hook can scan as it's written. It
doesn't catch a skill or agent's own definition going stale on its own - a
tool grant copied from another file and never trimmed, a reference to
something renamed. Added `.claude/TUNING-LEDGER.md` (friction logged the
moment it's noticed, per new `Feedback/procedure-drift-logging.md`), a
`SessionStart` hook (`.claude/hooks/tuning-ledger-check.js`) that flags any
unresolved line, and `procedure-tuner` to review and fix what the ledger
points at.

Seeded one real issue to prove it end to end: gave `inventory-researcher`
a dead `Edit` tool grant (its own text says it never writes a file) and
logged it to the ledger. A fresh agent given only `procedure-tuner.md`
found it, removed the grant, and closed out the ledger line - no other
issues turned up in that file, nothing else needed flagging. Full
report in `examples/self-tuning-session.md`. Nothing left open.

### 2026-01-21 - Built commitment-tracker from a self-extension session

Instead of describing a new automation up front, pointed the agent at a
folder of saved short-form videos and asked it to find what was actually
worth building. Browser automation can only read what's visible on
screen (captions, on-screen text), not watch or listen, so a couple of
videos with tips only in spoken voiceover were skipped and flagged rather
than guessed at.

Came out of it with six candidate skills, each tied to a real gap rather
than a video's premise on its own: decision-review, session-notes,
commitment-tracker, downloads-tidy, source-lookup, evening-review. Built
one (`commitment-tracker`, plus `TODO.md` as its target file) end to end
and verified it the same way as the rest of this repo, a fresh agent ran
it for real on `examples/sample-call-notes.md` with no expected output
written first. It correctly excluded the caller's own promise and a piece
of undecided discussion from the notes, and didn't invent a deadline
where none was stated. Full writeup in
`examples/skill-generation-session.md`.

Declined: a "watch competitors automatically" idea (no actual list of
competitors to point it at) and a standalone "always-on advisory panel"
idea (would have just been decision-review running in the background).
The other five candidates are documented but not built, open for later if
a real need for one of them shows up.

### 2026-01-14 - CLOSED_Added style-guard hook after repeated superlative/em-dash violations in listing copy

Third time in two weeks a listing draft went out with a banned
superlative or an em dash despite the rule being documented in
`Feedback/no-marketing-superlatives.md` and re-read at the start of the
`product-listing` skill. Decided documented rules alone weren't holding
across sessions, so added `.claude/hooks/style-guard.js` as a `PreToolUse`
hook on `Write`/`Edit` - scans content for the banned phrase list and the
em/en dash characters, denies the write outright if either is found, with
the offending snippet quoted back.

Verification: a real `Write` call with a deliberate violation, inside a
Claude Code session, has to be rejected before any file is touched. A
terminal run of the hook is not enough on its own, see
`examples/hook-verification.md` for both and for why. Nothing left open.

Correction added 2026-10-13: the hook as written on this date printed its
deny in a shape Claude Code ignores, so inside Claude Code it blocked
nothing until 2026-10-13, when a real headless session showed the write
going through and the output was fixed. "Nothing left open" was wrong; the
full account is in `Feedback/no-marketing-superlatives.md`.
